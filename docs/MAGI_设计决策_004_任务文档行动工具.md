# 设计决策004：任务文档行动工具

日期：2026-10-30。先补设计，再实现第19轮。

依据v0.3第12节“一个有用的行动工具”，新增独立于原文下载的任务工作单：固定模板包含所选计划全文、准备检查、执行记录、验收与反馈区域。首版不调用模型，不从自由文本猜测步骤，不生成研究结论；用户可在生成后的Markdown文件中编辑、填写。

流程：选择已保存版本 → 创建持久预览 → 核对正文和输出位置 → 显式确认 → 本机创建文件 → 返回实际文件与摘要。预览不会创建任务文件；不修改计划、记忆或背景版本。

预览绑定owner、计划ID、精确版本、内容SHA-256和请求ID。同请求同参数返回同一预览，改参数拒绝。可以明确选择历史版本，文档标注版本，不暗称最新；已需复核的计划可生成，但必须在文档及页面提示。

输出固定为业务数据库同级的task-documents目录，文件名由程序生成，不接收用户路径。首次确认后把完整临时文件原子链接到最终文件名，不覆盖既有文件；随后标记CREATED。文件已创建而数据库标记未完成时，同一确认可核对完整摘要后恢复。不同内容、链接、缺失的已完成文件报告冲突，不声称成功，不自动覆盖或修复用户编辑后的文件。

任务文档使用独立持久记录，不冒充计划保存的Operation回执。document_id标识一次工具产物；request_id用于预览去重；plan_id/version标识输入；payload_hash绑定确认正文。确认必须为严格布尔true且摘要匹配。当前仍为单用户、本机、单worker服务；不提供多账号隔离或任意命令执行。

验证包括预览不落文件、显式确认、重复确认、版本固定、跨owner拒绝、文件冲突、文件创建后状态提交中断恢复及接口流程。无需为此调用付费模型。实际浏览器验证与离线测试分别记录，不互相替代。

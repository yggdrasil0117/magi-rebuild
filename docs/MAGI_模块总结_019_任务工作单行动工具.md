# 模块019：任务工作单行动工具

日期：2026-10-30。先补充[设计决策004](MAGI_设计决策_004_任务文档行动工具.md)，再实现与验收。本轮接续仓库已有018终端功能。

## 本轮业务作用

在“我的计划”选择已保存版本，点击“准备任务工作单”，核对完整预览与输出位置，再点击“确认在本机创建文件”。服务创建可编辑的Markdown文件，默认位于业务数据库同级的`task-documents`目录；默认配置通常是`.magi/task-documents`，以页面显示的绝对路径为准。

以前的下载功能是计划原文副本。本工具保留精确版本原文，并增加准备检查、执行记录表、完成检查和反馈修订区域。首版使用固定模板，不调用模型、不自动拆解自由文本、不额外生成结论。表格里的步骤和结果由用户填写。创建文件是本轮实际行动，计划中的学习、采购、研究等任务没有因此执行。

生成后的文件可以用文本编辑器修改；网页预览保留创建时快照，不同步外部编辑。重复确认会核对文件，若已编辑、移走或发生冲突则明确报告，不覆盖、不自动重建。此时CREATED只描述历史创建记录，不等于文件当前仍与预览一致。

## 请求经过哪些模块

网页`app.js` → FastAPI严格参数与凭据校验 → `WebService.document_action`串行门 → `personal/documents.py` → SQLite预览记录及固定目录文件。

1. 预览接收计划ID、明确版本和请求ID，读取不可变版本并持久保存完整输出。此时没有任务文件，也不创建输出目录。
2. 用户确认时提交文档ID和预览摘要，且`confirmed`必须是布尔true。服务端使用已存正文，不接收任意路径或新正文替换预览。
3. 将临时文件完整写入并刷盘，再通过同目录硬链接发布到最终文件名，避免覆盖与半份最终文件。之后把文档状态标记为CREATED。
4. 返回确认时已核对的文件路径、正文、摘要与`verified=true`。不修改计划版本、记忆或context_epoch，也不伪造计划Operation回执。

接口包括POST `/v1/plans/{id}/documents`预览、GET同路径按版本恢复最近20条记录、GET `/v1/documents/{id}`读取原快照、POST `/v1/documents/{id}/confirm`确认。全部需要本机服务凭据。

| 标识 | 对象与用途 |
| --- | --- |
| plan_id + version | 作为输入的已保存计划精确版本，历史版本也可明确选择 |
| request_id | 一次预览请求，断线重试返回原预览，换参数拒绝 |
| document_id | 独立的工具产物记录，同时决定程序生成的文件名 |
| payload_hash | 完整预览UTF-8字节的SHA-256，绑定确认内容 |

刷新、重新连接并再次打开对应计划版本，可恢复最近预览或创建记录。切换版本后的迟到响应不覆盖当前详情。预览固定输入版本；计划后来更新不会把旧工作单伪装成最新版。背景变化提示取自预览时状态，工作单不作为执行任务的自动授权。

## 最重要的失败边界

SQLite与文件系统不能靠一次数据库事务共同提交。若文件已经发布、数据库状态尚未提交就中断，预览仍可能是PREVIEW。再次确认时核对已存在文件的完整字节，相同则补记状态；不同则拒绝。数据库事务覆盖这次短文件操作，不涉及模型或网络等待。

请求不接受路径；目录和文件链接被拒绝，文件名为服务生成的编号。已有用户文件不会被覆盖。硬链接需要本机文件系统支持，失败返回DOCUMENT_IO_ERROR，保持可重试状态，不降级成覆盖写入。真实断电、磁盘损坏和外部进程恶意竞态不在本轮保证范围；崩溃时可能遗留不被当作产物的临时文件，尚未增加自动清理。

业务schema从4升级为5，新增独立`task_documents`表，保留计划、记忆等数据。旧程序不能读取schema5；未对用户真实数据库进行回退试验。当前仍是单用户单worker，本轮owner过滤不等于多账号隔离。

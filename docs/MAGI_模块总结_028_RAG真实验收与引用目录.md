## 1. 业务问题和交付范围

用户开启三人格后，程序检索资料并冻结原文，三个角色分别分析，再综合为候选。上一轮已验证确认保存、文件修改和重启不覆盖历史依据，缺少真实模型能否正确使用资料的证据。本轮建立固定真实调用入口并实际运行，同时修复长上下文导致资料无法引用的问题。

本轮完成：固定四例真实调用脚本、所有调用失败证据、资料引用目录席位修复、综合提示中的资料权限边界、鉴权失败后的评测停止机制与离线回归。未完成：真实模型的引用支持与内容复核，初次原因为执行器传入了被截断的值；更正后的复测见末尾。没有因故障启动本地模型，也没有自动切换其他模型服务。

## 2. 一次业务请求经过哪里

用户输入 → WebService组装上下文 → MagiLocalRetrievalProvider检索当前授权资料 → 冻结retrieval到web_turn → 三角色接收同一snapshot → source_options编制目录 → 综合模型选择source_ids → selected_excerpts还原原文 → check_content核对来源与适用预算 → 展示候选 → 用户确认后才保存正式计划。

本轮真实评测只运行其中“本地检索 → 冻结输入 → Council真实生成 → 引用校验”部分。它不调用WebService确认接口，不保存正式计划，不执行行动，不测试浏览器或真实服务进程重启。它的独立retrieval.db仍会保存合成资料版本，但随后随临时目录清理；不能把“评测写了资料索引”理解成“确认保存了用户计划”。

## 3. 核心修复：检索命中不等于有可选引用

旧目录按用户问题、记忆、资料的顺序填充，最多24项，每项160字。一个8000字问题就足以用完目录，资料虽然在快照中，却没有source编号，综合模型因此无法通过编号选择它。

当前Provider最多返回五条、每条160字。先为这些实际资料生成编号，随后放入问题和记忆，仍限制24项。因此长上下文下资料能够进入目录。这里改变的是引用编号分配，不是指令优先级：用户要求仍是约束，资料不能发布程序指令。

### 3.1 实际核心代码

文件：`src/magi/council/sources.py`。

```python
def source_options(snapshot):
    """从当前消息和有效记忆切出原文片段，最多24项、每项160字。

    目录有界且顺序确定；未进入目录的文字仍在快照中，但不能通过编号引用。
    不改写原文，不把历史助手意见或旧计划登记成当前用户陈述。
    """
    # 先给本轮最多五条资料分配目录席位，避免长问题/记忆占满24项后资料无法引用。
    # 顺序只影响本轮source编号，不代表资料比用户要求更有权威。
    sources = [
        (m["evidence_ref"], m["quote"])
        for m in snapshot.get("retrieval", {}).get("matches", [])[:5]
    ]
    sources += [("user:current", snapshot.get("question", ""))]
    sources += [
        ("memory:" + m["key"], m["value"]) for m in snapshot.get("memories", [])
    ]
    options = []
    for ref, text in sources:
        if ref not in snapshot.get("evidence_ids", []):
            continue
        for start in range(0, len(text), 160):
            quote = text[start : start + 160].strip()
            if quote:
                options.append(
                    {
                        "id": f"source:{len(options)}",
                        "evidence_ref": ref,
                        "quote": quote,
                    }
                )
            if len(options) == 24:
                return options
    return options
```

函数参数` snapshot `来自WebService冻结的本轮输入，关键字段如下：

| 字段 | 从哪里来 | 意义 |
| --- | --- | --- |
| question | 本轮用户消息 | 当前目标或约束 |
| memories | 已确认且当前有效的记忆 | 不把模型猜测登记为事实 |
| retrieval.matches | 本轮Provider实际返回的原文 | 最多五条候选，不证明语义相关 |
| evidence_ids | 程序组装的本轮证据白名单 | 未登记的来源不得进入引用目录 |

返回列表中，`id`是本轮可选择的source编号，`evidence_ref`关联真实来源，`quote`是程序从快照取出的原文。函数不请求模型、不访问文件、不修改数据库。

检查`ref in evidence_ids`是为了防止未登记内容被目录自动接纳；160字窗口约束上下文；24项限制目录规模。用户问题和记忆剩余部分可能仍不进入目录，这一限制没有消失。编号先后也不代表来源质量排序。

例如资料是“导出不代表执行完成。”，用户问题非常长。新目录首项是：

```json
{"id":"source:0","evidence_ref":"document:chunk","quote":"导出不代表执行完成。"}
```

这里`document:chunk`只是教学示意，真实值由Provider的分块ID组成。`source:0`在下一轮可能指向别的原文，不是永久文档ID，不能跨快照解释。本轮改变了目录顺序，因此新旧回合source编号不可混用；旧候选已经保存的原文和来源引用不会被重新编号或修改。

### 3.2 模型选择后，程序做什么

```python
def selected_excerpts(ids, snapshot):
    """只解析本轮目录中已有的编号；返回原文，不进行模糊匹配或猜测修复。"""
    options = {item["id"]: item for item in source_options(snapshot)}
    if len(ids) != len(set(ids)) or any(key not in options for key in ids):
        raise ValueError("unknown source selection")
    return [{k: options[key][k] for k in ("evidence_ref", "quote")} for key in ids]
```

`ids`来自综合模型输出的`candidate.source_ids`，`snapshot`仍是同一冻结输入。函数重建本轮目录，拒绝不存在或重复编号，然后返回对应的真实原文。它不模糊猜测模型想引用什么，也不根据路径重新读取已变化的文件。

例如选择`["source:0"]`得到上面那份原文；选择`["source:404"]`抛ValueError，Council把它转成引用选择失败，没有可保存的综合候选。函数仅证明编号与原文匹配，不能证明原文支持计划里的每个结论。

## 4. 固定真实评测：参数、预算与保存边界

新脚本：`scripts/evaluate_rag_cloud.py`。

| 函数/参数 | 作用及来源 | 返回或副作用 |
| --- | --- | --- |
| main() | 读取`--output`和已有magi.qianwen.toml | 启动固定验收，不接收密钥正文参数 |
| evaluate(settings, output) | settings是已有云端配置；output是新报告路径 | 逐例写JSON报告，并在控制台打印状态；不返回计划 |
| CASES | 版本控制中的固定合成资料和问题 | 事先定义四例，不根据结果挑选 |
| Council.run(snapshot) | 使用真实模型适配器，最多三角色加一次综合 | 返回状态、候选及诊断，不执行计划保存 |

四个固定案例分别是：原词资料命中、同义改写且提示资料不足、新版资料、含指令性文字的资料。新版用同一路径修改内容，保留同一文档身份；旧版是否保留的程序边界沿用上一轮测试，本轮没有让模型比较两版完整意见。

每例最多4次生成，总上限16次；单次和整轮仍受Council原有超时约束。没有自动重试、修复模型输出或换模型。报告拒绝覆盖已有文件；每完成一个案例立即保存snapshot、结果、引用边界检查和延迟，保留成功与失败。source_sha256记录实际运行代码指纹，后续修复脚本不会改写原始报告指纹。

`selected_refs_exist`只检查所选原文来自本轮目录；空引用也满足该检查，因此另记`selected_document_refs`计数。即使有资料引用，仍须人工判断是否真正支持结论。模型用量只汇总返回的diagnostics，不根据字符数猜token；没有核实单价就不计算费用。

# MAGI 模块总结 015：已保存计划 Markdown 导出

日期：2026-10-30。

## 1. 对应哪项需求

整体计划v0.3第1节的P1体验改进明确包含“Markdown导出”；第12节还提及后续增加一个有用的行动工具，如导出研究任务或生成项目文件。

本轮实现前一项：**将已保存计划的指定版本生成可下载文档**。它不是最小MVP的新增必选项，也不是三人格自主执行器。此前把它笼统称为“行动能力”不够准确，实际能力以这里的边界为准。

## 2. 使用与实现

在“我的计划”打开计划，选择想要的已保存版本，点击“下载此版本（Markdown）”。没有新增主界面表单。文件包含计划标题、版本、原正文、保存时间、计划ID及正文SHA-256；正文不经模型改写，不把假设或建议变成执行结果。

```text
用户选择版本并点击下载
  → 带现有凭据请求 /v1/plans/{id}/export?version=N
  → 从业务库读取对应不可变版本
  → plan_markdown 生成文本
  → 浏览器下载 .md 文件
```

版本参数必须明确提供，下载不随“最新版”变化而漂移。前端点击时冻结计划与版本，即使之后切换详情也仍对应原先选择。导出不增加模型调用、不写计划、不生成新的业务操作回执，也不接受用户提供服务器写入路径。

重复导出同一版本的内容一致，不加入动态生成时间。正文摘要对应原始正文的UTF-8字节，不是整份文件摘要，也不证明建议内容正确。文件下载失败不会将计划标为已执行。

## 3. 验证总结

全套离线验证：**279 passed，19.48秒**，一个已有Starlette/AnyIO弃用警告。变更Python文件Ruff及格式检查、JavaScript语法检查通过。

新增集成测试验证：鉴权、版本必填和正数要求、缺失计划或版本404、未确认候选不能当计划导出、原正文保留、响应为UTF-8附件、标题转义，以及修订和背景变化后重复导出旧版本内容不变。导出不调用模型或增加业务写入。

真实Edge浏览器通过Playwright CLI操作独立演示服务，实际下载v2和v1文件，并逐一对照数据库正文、版本及正文摘要。导出后业务操作仍为预置的3次。截图已检查，浏览器和API进程已关闭。本轮不读取云端密钥或调用模型，演示计划为固定测试数据。

## 4. 限制与阅读

当前只支持Markdown计划副本，不支持DOCX/PDF、自动撰写新报告、任意文件生成、代码执行或模型自主调用导出工具。用户确认计划和用户点击下载是两个明确操作，导出本身不等于执行计划。

先读 `personal/export.py` 的纯函数，再看HTTP导出接口和 `app.js` 的 `downloadPlan`：三者分别负责文档内容、版本读取和浏览器下载。关键函数有中文说明。

本轮属于常规P1能力交付，没有解决新的重大工程瓶颈，不为凑条目写入question.md。完成后等待用户阅读复述，再决定下一项需求。

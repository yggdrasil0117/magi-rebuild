# MAGI 模块总结 013：页面最小交互优化

日期：2026-10-30。根据用户体验反馈，先降低操作门槛，保留原有配色与布局基础；原作风格美术由用户后续决定。

## 1. 现在怎么使用

1. 打开“设置”，填写启动终端提供的本机服务凭据，点击连接。页面会自动加载当前会话历史并收起设置。
2. 直接在输入框聊天，不需要填写会话、预算、计划 ID 或版本。
3. 需要比较方案或形成计划时，打开“三人格分析”开关再发送。
4. 阅读候选，决定是否保存；完整讨论和运行信息默认折叠。
5. 需要查看或修订时打开“我的计划”。反馈会自动选择最新版本及分析模式，返回聊天输入框。

当前会话沿用已有 `study`，高级选项仍允许手动查看其他会话；本轮没有新增多会话管理。连接认证仍由后端检查，没有在网页中嵌入服务密钥，也没有把凭据持久化。刷新后需要重新连接，这仍是使用门槛，后续可以单独改进。

## 2. 调整了什么

- 收起原来常驻的凭据、会话、模式选择器、时间预算、修订ID和版本参数。普通使用不需要接触这些字段。
- 主界面保留聊天输入、发送、三人格开关、“我的计划”和设置；计划详情按需打开。
- 候选主区域显示综合建议，三人格原始讨论、执行信息和候选摘要保留在折叠详情中，不修改数据库里的原始回复。
- 增加空输入提示与中文结果说明。失败时可以重试原消息，或取消本次重试重新填写；取消不会撤销已经发生的服务端处理。
- 保存状态从已提交操作中读取。刷新后，保存过的候选显示“已保存”，点击查看其真实版本，不再重复提交确认请求。
- 保存、反馈、版本冲突和幂等规则继续复用原有后端。没有新增模型工具、自动保存或鉴权绕过。

`WebService.proposal` 增加只读的 `saved` 信息；它先验证候选所属用户、会话和回复，再查对应的成功操作。模型说“已保存”仍不能产生这个状态。

## 3. 验证总结

全套离线验证：**277 passed，18.03秒**；一个已有 Starlette/AnyIO 弃用警告。变更Python文件Ruff和格式检查通过，JavaScript语法检查通过。现有闭环测试补充断言：保存状态中的计划与版本匹配真实回执。

真实浏览器使用Playwright CLI与Edge，连接独立FastAPI和SQLite；模型与checkpoint为模拟，不调用千问或本地模型。验证：

- 初始页面只有聊天输入和少量操作，连接和高级选项收起。
- 一次填写测试凭据后直接完成普通聊天，没有填写其他参数。
- 切换三人格开关后生成候选，完整讨论默认折叠，仍需显式确认。
- 确认保存后刷新、重新连接，恢复两条历史及真实“已保存”按钮。
- 点击已保存按钮仅打开计划，操作总数保持4，不新增保存；其中3次为演示预置数据。
- 计划反馈自动设置目标与分析模式，收起计划区域；退出修订恢复日常模式并清空目标。
- 桌面和390像素窄屏截图已查看，窄屏无横向溢出。

浏览器与本轮API进程均已关闭。最后将取消重试按钮调整为仅失败时显示，语法检查通过；未对该按钮新增断网故障注入验证。完整记录见 [013验证证据](validation/013-minimal-ui-evidence.json)。

# MAGI 当前使用指南

## 联网查资料（模块034）

停止服务后运行`.\.venv-harness\Scripts\python.exe -m pip install -r requirements-mcp.lock.txt`，再按下文正常启动。已有千问配置不变；当前联网使用Exa官方匿名MCP服务，有额度和可用性限制，不需要把模型密钥填给Exa。

在日常聊天输入框旁勾选“联网查资料”，提出具体问题，建议说明适用版本并要求官方来源。模型可调用搜索和网页读取，回复下方展开“本轮联网资料”可核对实际网址、片段、状态和时间。它保存的是当时收到的片段，刷新后重新连接并加载原会话仍可查看，不会再次查询。

每轮最多3次联网调用，搜索最多3条、每条2000字符，读取最多保留4000字符。长网页可能没读到目标章节；链接真实和流程完成都不保证回答正确。查询词、查询目的和网址发给外部服务，返回片段送给千问；没有自动隐私脱敏，不要提交不愿外发的信息。失败不会自动切换本地模型或重试；重新查询请发新消息。

联网开关在当前页面保持选择；切换三人格或刷新会关闭。当前只接日常聊天，没有接入三人格共享证据、终端开关或自动写入计划及有效记忆。原有自动记忆建议可独立关闭。安装细节、核心代码、真实失败和学习问题见[模块034总结](MAGI_模块总结_034_MCP联网资料查询.md)。

更新：2026-11-02。当前能力包括独立RAG和计划版本级执行跟踪；历史验收与本轮验收分开记录。

适用：Windows、Python 3.12、本机单用户、千问云端模型。先使用原生网页完成主流程，Open WebUI和终端是可选入口。

## 1. 启动

在项目目录打开PowerShell。已有`.venv-harness`时直接运行：

```powershell
.\scripts\start_magi.ps1
```

启动时可能分别要求输入千问API Key和硅基流动API Key：隐藏输入，仅传给当前进程。千问负责生成，硅基流动BGE-M3负责已启用的向量检索。随后窗口会显示**本机服务凭据**，复制它用于网页连接。这些凭据用途不同：模型API Key用于调用千问，本机服务凭据用于访问自己的MAGI后端；不要把模型API Key填进网页。

打开[本机聊天页](http://127.0.0.1:8765)，展开“设置”，粘贴本机服务凭据并点击“连接”。默认会话可以直接使用，不需要先填写计划ID、版本号或预算。刷新页面后凭据为空，需要重新连接。

关闭服务：在启动窗口按Ctrl+C。先不要关闭窗口中的错误信息；启动或生成失败时保留错误码，方便定位。不要同时启动多个worker或reload。

首次安装环境时运行以下命令，已有环境不必每次重装：

```powershell
python --version
python -m venv .venv-harness
.\.venv-harness\Scripts\python.exe -m pip install -r requirements-qianwen.lock.txt
.\.venv-harness\Scripts\python.exe -m pip install --no-deps -e .
.\scripts\start_magi.ps1
```

要求Python 3.12。锁文件包含harness、Web和千问适配依赖；不需要为了运行云端模型下载Ollama。脚本策略受限时可用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start_magi.ps1
```

## 2. 走完一条主流程

1. **日常交流**：默认“三人格分析：关闭”，直接发送问题。普通聊天可查询资料或已有计划，不一定形成计划。
2. **重要取舍**：开启“三人格分析”，说明目标、约束、未知项及完成条件。展开回复中的讨论详情可看三个真实观点。若有硬性总时间预算，可在设置→开发者选项填分钟；程序不会可靠地从任意自然语言自动抽取全部硬约束。
3. **确认保存**：核对候选的步骤、假设、未知项后，点击“确认保存此候选”。生成成功不是保存成功；正式结果在“我的计划”中可查。
4. **查看与恢复**：打开“我的计划”选中标题，切换版本查看。停止并重启服务后，使用同一数据目录仍可查询，不需要重新生成计划。
5. **记录与复盘**：先在“执行跟踪”选择状态，填写实际进展、阻塞或结果，点击“确认记录执行情况”。这一步只保存用户记录，不调用模型。需要调整安排时，再点击“对最新版提交反馈”，填写目标或约束变化；系统结合近期记录生成修订候选。再次确认才新增版本，新版从未开始独立跟踪，原版本及记录保留。开始反馈后可修改预算，或点击“退出修订”。
6. **执行材料**：在已保存版本中“准备任务工作单”，核对后批准或拒绝。批准才创建Markdown文件，输出位置在页面显示。文件只是执行材料，不代表学习或采购等事项已经完成。

工作单拒绝后不能批准原预览；需要时准备新工作单。重复核对已创建文件不会新建或覆盖用户编辑。批准已保存但执行中断时，只在明确重试时恢复；BLOCKED表示需要核对实际文件或重新准备，启动和GET不会自动执行。

## 3. 记忆和资料

自动记忆建议可以在设置中暂停。候选只有经用户确认才成为有效长期记忆；忽略记录也会保留，不等于会话结束删除。个人记忆可在页面管理，修改会影响有效上下文和旧候选。

资料搜索只在配置的`[tools].root`授权目录中读取UTF-8 Markdown/TXT/RST。返回原文路径和行号，但有预算和大小限制；搜索覆盖不完整或没结果不代表所有资料没有答案。不是互联网搜索，也不是已经建好的向量知识库。

## 4. 成功与失败怎么判断

- 模型回答、候选、正式计划、工作单文件是不同对象；以真实保存记录、版本和文件核对结果为准。
- PARTIAL或FAILED不代表完整审议，不会提供可保存的完整候选；保留失败事实后，可新发更清楚的请求，不会自动重试。
- 发送断线时，再点发送会重试同一消息编号，避免重复生成；“取消这次发送”只放弃客户端重试，不撤销服务器已经完成的操作。
- 背景或计划版本变化可能使候选过期，需重新生成。旧版本仍可读取，不代表仍适用于当前情况。
- 模型仍可能误解要求、遗漏条件或提出不合适建议；结构检查通过和流程完成都不是内容正确的保证。

模块033修复了新会话先审议后被误判为未完成推理的问题。升级前的旧会话若仍提示“有未完成推理”，不要删除数据库；在设置的“会话”换一个新名称并点击“加载历史”，再从“我的计划”继续反馈。旧计划保留。系统不会自动清除历史会话的待执行任务，以免抹去真正的中断状态。

当前没有完整账号登录、多人隔离、任意终端执行或通用自主行动能力。Open WebUI与终端的交互适配范围见各自文档，工作单完整批准/拒绝入口以原生网页为准。

## 5. 数据与验收

默认业务数据和checkpoint在`.magi`目录，以`magi.qianwen.toml`为准。审批checkpoint与业务库同目录，备份时一起保留；不要为了重试清空数据。历史显示、推理checkpoint和已确认业务记录职责不同。

产品范围和分轮验证状态见[MVP交付清单](MAGI_MVP交付清单.md)与[模块033整体验收](MAGI_模块总结_033_当前版本整体验收与试用收尾.md)。第24轮和第32轮的浏览器证据仍按各自时点理解。开发验收使用独立数据，不能把演示目录当正式个人数据。

首次试用建议只选择一件真实的小事，例如“本周核对一个登录接口问题”。先保存一版计划，再记录一次阻塞，提交反馈并核对修订理由，最后重启服务查看两个版本。核对内容是否符合实际条件，避免仅凭状态或绿色提示判断建议正确。

需要备份时先Ctrl+C停止服务，再复制配置中整个数据目录（默认`.magi`），同时保留配置与授权资料。不要在运行中仅复制单个SQLite文件，也不要只备份计划正文：业务库、聊天checkpoint、审批checkpoint和向量缓存有不同职责。恢复到新的目录后还需要让配置指向对应文件。本轮没有实现一键备份，也没有做备份还原演练；实际API重启恢复不等于备份恢复已验证。

离线检查：

```powershell
.\.venv-harness\Scripts\python.exe -m pytest -q
```

早期的`verify_web_mvp.py`及旧截图对应旧版界面，不能直接当当前页面验收说明；当前原生网页流程以本指南及第24轮证据为准。


## 授权资料的云端向量检索

当前magi.qianwen.toml的`[embedding]`已明确启用BGE-M3，环境变量为SILICONFLOW_API_KEY，与千问DASHSCOPE_API_KEY分开提供。启动脚本会隐藏询问缺失值，不自动读取或保存个人凭据文件；网页仍只填本机服务凭据。

开启三人格时，程序将授权tools.root范围内、预算允许的原文片段和问题送给硅基流动生成向量，再将相似候选冻结给三人格。页面“本轮参考资料”可查看原文和版本；向量失败会明确标记退回关键词。无结果不等于资料没有答案，相似度不等于事实正确。

如不使用云端向量，把`[embedding].enabled=false`。该选项不关闭千问生成；两者用途不同。现阶段最多前128块参与向量检索、返回前5条，缓存保存于业务库同目录retrieval.db；修改文件会产生新版本向量，旧计划原文保留。向量缓存及资料索引不代表正式计划已保存，仍要点击确认。

更新后若页面仍显示旧来源标签，可Ctrl+F5强制刷新，然后重新填写本机服务凭据连接。详细代码、固定案例、误召回及验证限制见[模块029](MAGI_模块总结_029_硅基流动BGE_M3向量检索.md)。


## 核对候选是否仍围绕本轮目标

资料里出现的操作，不等于你已经要求执行该操作。保存前请重点看：候选是否增加了不需要的迁移、采购或其他行动；新增前提是否明确列为假设/待确认；“没找到资料”是否被扩大成“资料库不存在答案”；核对失败或证据不足时是否仍可记录结果。

当前三个角色和综合均收到目标/证据指导，但模型仍可能违反。引用合法与流程COMPLETED不保证建议正确，确认保存前仍需判断。[模块031](MAGI_模块总结_031_目标与证据边界及内容对照.md)保留真实前后结果与未解决例子，含核心代码和面试知识关联。


## 计划执行跟踪与复盘

打开“我的计划”选中计划，找到“执行跟踪”：选择未开始、进行中、遇到阻塞或已完成（用户记录），写实际进展、问题或结果说明，再点击“确认记录执行情况”。这次记录不调用模型、不改计划正文、不自动执行任务，状态与说明会持久保存；完成自报不等于系统核验。

“查看执行记录历史”显示当前查看版本最近50条。切换历史计划版本可以看它自己的状态；列表只显示最新版。允许追加纠正或重新开始，旧记录不会删除。

需要调整时，点击“对最新版提交反馈”，补充当前目标和约束。该版本最近3条记录（每条最多300字）会提供给三人格，生成后仍要确认才形成新计划版本；新版不会继承旧版完成状态。如果生成后又更新执行记录，旧修订候选会要求重新生成，避免使用过时进展。

断线时“重试原执行记录”保留同一提交；不要换内容反复提交。放弃重试不会撤销服务端可能已保存的记录，应先核对历史。其他窗口已更新时，页面刷新状态后请重新核对再确认。停止和重启服务后，计划和执行记录仍可恢复。

当前为本机单用户、计划版本级记录，没有逐步骤任务树、后台自动执行或完成证据自动核验。代码、验证、保存边界和面试关联见[模块032](MAGI_模块总结_032_计划执行跟踪与复盘.md)。

## 长会话与语义记忆（模块035）

日常聊天达到容量阈值时会尝试压缩较早轮次，最近三个轮次与网页原始历史仍可查看。摘要失败时沿用容量检查，必要时提示新建会话。

要试用跨会话语义召回，在现有环境执行 `pip install -e '.[memory]'` 并配置硅基流动凭据。连接页面后，勾选「语义召回个人记忆」。本轮问题与待索引的已确认记忆会发给硅基流动。回复下方可查看实际注入的记忆版本。索引暂不可用时会标明状态。SQLite 继续保存有效记忆，独立 Qdrant 目录可由业务库重建。

参见[模块035学习总结](MAGI_模块总结_035_会话压缩与语义记忆.md)。

## 后台任务

日常聊天或三人格分析发送前可以勾选「提交为后台任务」。服务登记后可以关闭页面。重新连接同一会话，展开「后台任务」查看状态，完成后页面自动加载聊天。每个会话一次处理一条后台任务，后台完成后不自动提取记忆建议。

服务重启后，等待执行的任务继续排队。已经开始但没有可确认结果的任务会显示中断，应先核对历史与独立工具产物，再决定是否新发消息。[模块041](MAGI_模块总结_041_后台任务运行与恢复.md)

## GitHub Issue 草稿与批准

在服务进程配置 `MAGI_GITHUB_ISSUES_REPO` 和 `MAGI_GITHUB_ISSUES_TOKEN` 后，日常聊天可勾选「启用 GitHub Issue 草稿」。提出问题后展开草稿，核对目标仓库、标题与实际正文，再选择批准或拒绝。若显示结果待核对，请在仓库中找到对应 Issue，输入编号只读核对。刷新历史可以再次查看原草稿和回执。[模块042](MAGI_模块总结_042_受控创建GitHubIssue.md)

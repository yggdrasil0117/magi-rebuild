# 模块027：独立本地RAG与三人格证据闭环

日期：2026-11-01。依据设计决策010完成首轮实现及离线/浏览器验收；真实模型内容验收待提供凭据。本文件取代同名的初始进度说明，原先失败和尝试仍保留在验证记录中。

## 业务作用与使用

把资料放入TOML配置的`[tools].root`（目前为docs），正常启动MAGI，开启三人格分析并提出相关问题。程序先读取授权资料，再让三个角色依据同一份冻结原文分析；页面“本轮参考资料”可查看来源、版本、原文与覆盖提示。没有结果或检索失败会显示状态，不意味着资料不存在答案。候选仍须点击确认才能写入正式计划。

只支持UTF-8的md/txt/rst，排除隐藏命名、依赖目录和链接。沿用200条目、40文件、单文件32768字节、总262144字节扫描预算；最终最多5条、每条160字。没有上传、PDF解析、向量、外部服务或本地模型启动。

## 模块与边界

`agent/search.py`提取共用扫描函数，旧日常搜索工具参数与行为保持不变；新scan_documents收集完整读到的文本，不开放额外模型参数。

`retrieval.py`定义RetrievalRequest/Provider与本地实现。每轮只扫描一次，以当前实际读取版本排序；英文按词、中文按双字窗口，最多40个去重查询词，按命中的不同查询词数降序，再按路径和位置确定排序。这是关键词重合基线，不是BM25或语义支持判断。英文词采用子串匹配，中文常见双字可能误召回，跨160字边界的词可能漏召回，不承诺质量。

本机FTS5已通过可用性测试；本轮暂不使用其默认分词作为中文排名，先保留简单可解释基线，未加入额外中文分词依赖。分块按行切160字，保留原始行号和行内offset；不跨行拼接或改写。

独立`retrieval.db`放在业务库同目录，包含documents、versions、chunks，不改变业务库schema。文档ID绑定授权根目录与相对路径，重命名视为新文档；版本ID绑定文档和实际文件字节SHA256；分块ID绑定版本、行号与行内位置。这些ID只标识资料，不是回合、候选、计划版本或操作回执。根目录移动也会改变文档身份。

旧版本只追加保留。每轮候选只来自当前扫描，删除或读取失败的文件不会从旧索引恢复成当前依据。扫描并非整个目录的原子时点：扫描期间变化可能影响覆盖，但每份证据绑定实际读取字节；历史索引没有清理和容量治理，属于当前限制。索引失败返回FAILED，不回退旧缓存冒充当前结果。

`web/service.py`将资料结果冻结到现有web_turn，并在首次模型调用前持久化；三个角色读取同一snapshot。`council/sources.py`建立引用目录，模型选已有编号，程序还原原文并核对引用；资料命中回合拒绝手写摘录绕过目录。目录最多24项，过长问题/记忆可能挤占可引用目录，未做无限上下文处理。

确认计划后，所选资料路径、版本与原文进入计划正文，计划来源仍关联web_turn。资料后来修改不重新计算旧候选或改写旧计划；用户确认、程序结构校验和内容是否正确仍是不同事实。日常聊天继续使用原有搜索工具，本轮新增资料快照自动接入三人格。

# 设计决策008：工作单持久审批接入

日期：2026-10-31。第23轮先设计后实现，接续第22轮成熟机制验收。

准备工作单预览后，使用LangGraph StateGraph、interrupt与SqliteSaver建立待审流程。动作已确定，不用脚本模型或额外LLM调用伪造一次工具选择；模型仍只有准备预览能力，最终创建由网页上的用户决定触发。

审批图包含等待决定与执行节点。暂停位置保存在业务库同目录、独立的审批checkpoint文件中。业务schema7新增document_approvals，绑定document_id、owner、冻结摘要、interrupt_id、不可变决定和安全错误码。框架负责暂停与恢复，业务表负责用户决定及重复/相反决定边界，TaskDocuments.confirm继续负责实际文件一致性。

现有确认API保留，严格confirmed=true，新增可选interrupt_id；新网页始终发送实际中断编号。旧客户端没有中断编号时仍须提交精确摘要，且只能决定该文档的唯一当前审批，不可覆盖拒绝或相反决定。新增拒绝入口，仍验证凭据、owner和摘要。GET只读状态，不自动执行工具。

默认单用户、单worker，所有修改沿用服务串行门与应用锁。首次决定先持久提交再恢复图；相同决定重试读回原事实，相反决定拒绝。已批准而进程中断的流程只在用户明确重试时恢复，不在服务启动或GET中重放。工具明确失败时标记BLOCKED，不自动重放；若业务库已CREATED，重复确认仍以原业务服务核对真实文件。跨业务库、checkpoint和文件系统没有单事务原子性，不声称恰好执行一次。

拒绝结束该文档审批，原始预览仍保留。准备新预览使用新请求ID，不解除旧拒绝。页面区分待审批、已拒绝、执行受阻与实际文件创建，内部ID按需处理，不扩展视觉设计。

验证覆盖认证、严格确认、摘要/owner/过时中断、重复/相反决定、并发决定、旧版预览兼容、失败、显式恢复以及真实浏览器批准/拒绝与服务重启。保持原资料检索与三人格回归，不增加付费模型调用来验收确定性审批。

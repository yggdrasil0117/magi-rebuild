# MAGI 模块总结 008：计划内容一致性

日期：2026-10-30。完成本轮代码与离线验收；尚未进行新结构的千问真实生成验收。

## 1. 本轮解决什么

007 中 12 份云端候选均通过结构校验，但人工阅读发现 5 份时间表述需澄清。本轮在计划操作界面之前，先改善计划的表达与可检查性。

新候选的每个步骤明确填写：活动、完成条件、正整数分钟、时间类别。类别只有任务 `work`、纯休息 `rest`、复盘 `review`、预留缓冲 `buffer`。提示要求混合活动拆步，最多六步；程序按类别汇总，各步骤计入一次，并保留总预算校验。

例如，过去“90 分钟休息和复盘，同时累计休息 90 分钟”容易误读。现在应写成“休息 60 分钟 + 复盘 30 分钟”，程序显示休息 60、复盘 30、合计 90。缓冲单独列出，不会在程序汇总中被算成休息。预算是上限，不要求填满。

**程序能验证字段和算术，不能仅凭类别证明文字含义正确。** 模型仍可能把“休息并下单”错误标为纯休息；这种语义错误需要人工复核，不能声称已全面解决。

## 2. 用户陈述、假设与未知项

候选增加两个字段，并保留原有假设：

| 字段 | 含义 | 程序检查 |
| --- | --- | --- |
| `source_excerpts` | 当前用户消息或有效记忆的连续原文摘录，带 `evidence_ref` | 引用必须存在，摘录必须逐字出现在对应来源 |
| `assumptions` | 模型为提出方案采用的待确认假设 | 有界文本，不代表用户已认可 |
| `unknowns` | 影响执行但还缺少的信息 | 有界文本，显示在候选和保存正文中 |

“用户陈述”不等于外部核实的事实。引用检查也不保证上下文、相关性或推理正确；例如断章取义仍可能匹配原文。模型意见、历史助手回复和旧计划不作为本轮摘录来源。旧计划仍用于解释修订，最新反馈优先。

综合结论原有的 `unknowns` 继续展示；候选自己的 `unknowns` 用来随计划正文保存执行所需的待确认事项。二者可能有重合，但都不是自动生成的记忆。

## 3. 调用链和保存位置

```text
相同快照 → 三份人格意见 → 综合生成候选
  → 校验分类、整数用时、原文引用、总预算
  → 程序汇总时间分类 → 展示待确认候选
  → 用户确认 → 冻结正文保存到计划版本
```

仍然最多四次模型调用，没有增加评审模型、自动修复或自动重试。修订理由的提示要求解释保留和放弃，避免重复分钟数字；这是一项生成指引，并非程序保证。

新生成结果的结构化内容仍在业务库的回合结果中保存。确认后的计划正文包含分类汇总、原文依据、假设和待确认事项，因此重启查询及新版本保留这些信息。没有新增数据库或修改表结构，也没有把模型假设自动写成确认记忆。

新候选缺少分类、用时或摘录匹配失败时返回 `PARTIAL`，不产生可保存候选，网页显示中文原因。历史候选仍可解析；缺少分类时明确提示旧版数据需要人工复核，不猜测补全类别。历史已经保存的正文不重写。

最终结果：**252 passed，14.41 秒**；新增 20 项测试。一个已有 Starlette/AnyIO 弃用警告。变更 Python 文件的 Ruff 检查与格式检查通过。

覆盖范围：

- 上轮五类歧义的明确分配样例：学习 80/休息 10；下单 10/休息 45/缓冲 5；任务 270/休息 60/复盘 30；任务 180/休息 30/复盘 30；下单 10/休息 50。
- 新增预约维修场景：任务 7/休息 13/复盘 4/缓冲 6，合计 30，低于预算 40。
- 拦截缺少类别、缺少分钟、非法类别、超预算、虚构来源、虚构摘录和改写而非逐字引用；布尔值、数字字符串、小数不能冒充整数分钟。
- 无显式预算时仍要求分类和分钟；允许匹配有效记忆中的原文。
- 网页生成 → 确认保存 → 重复确认 → 服务对象重建及数据库读取 → 修订 v2 → v1 保留。断言新增内容出现在保存正文中。
- 网页引用核对失败时不产生 proposal 或保存计划；旧候选仍能读取。

五个歧义回归样例是**人工编写的明确方案**，验证新结构和调用链能表达及保存正确分配，不是模型自动修复上一轮输出。原始 007 证据保持不变。

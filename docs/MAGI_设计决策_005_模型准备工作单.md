# 设计决策005：模型通过工具准备工作单

日期：2026-10-30。第20轮先补设计，再实现。

沿用第19轮的工作单预览与人工确认。新增日常聊天工具`magi_prepare_task_document(plan_id, version)`，通过现有Deep Agents function calling执行，不接MCP。模型仅能准备持久预览，不能传owner、确认标记、文件路径、任意正文或写文件命令。正式文件创建继续走用户页面确认入口。

工具由WebService在当前聊天轮次中注入，owner、turn_id、请求去重编号均由程序绑定。普通CLI与三人格快照读取不自动获得此工具。对同轮同版本的重复调用返回同一预览；不同轮可准备新预览，不把旧工作单或用户编辑覆盖。

预览记录新增可空source_turn_id，关联实际Web轮次。旧版手动预览保留为空。历史与轮次响应附带当前owner的真实文档摘要，网页独立于模型文字显示查看按钮；即使模型末尾回答失败，已生成预览仍可查，不伪造回答COMPLETED。工具结果只返回文档编号、计划版本、PREVIEW状态与确认说明，不回灌整份文档、不声称文件创建成功。

沿用现有模型/工具调用预算，不自动重试或让模型确认文件；无相关需求时不应调用该工具。系统提示词是行为指导，真正的文件权限边界来自未注册确认/写入工具、严格参数和现有后端确认流程。测试区分脚本模型的实际工具执行、真实千问是否选择工具、浏览器是否能查看并确认，不能混为同一验收。

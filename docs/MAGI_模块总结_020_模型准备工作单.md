# 模块020：模型通过function calling准备工作单

日期：2026-10-30。先补充[设计决策005](MAGI_设计决策_005_模型准备工作单.md)，再实现本轮。用户已复述通过“候选与生效记录不同”“编辑文件不等于新增计划版本”的关键边界。

## 1. 本轮业务变化

第19轮需要先打开计划、点击“准备任务工作单”。现在也可以在**日常聊天**中说：“请为已保存的后端学习计划准备任务工作单预览，先不要创建文件。”模型可以查询计划，再调用`magi_prepare_task_document`准备预览。回复下方的“查看待确认工作单”来自数据库真实关联记录，用户点击查看、核对后，仍须在网页确认创建文件。

文件内容继续使用第19轮固定模板，不额外调用模型撰写，不自动拆步骤。没有接入MCP，也没有开放文件创建、任意路径、计划写入或自动确认工具。三人格生成和确认保存流程保持原边界。

新增的是**一个可由模型选择的预览工具**，不是第一次为整个MAGI引入function calling。此前日常会话已有文件读取、计划查询等模型工具。工具预览会写入待确认业务记录，因此不能再笼统说所有工具均只读；未开放的是正式计划写入和最终文件创建。

## 2. 请求链路与关键检查

```text
用户自然语言请求
→ WebService建立RUNNING轮次，服务端绑定owner和turn_id
→ 日常Harness向模型提供允许的工具与参数说明
→ 模型选择查询计划 / 准备工作单
→ 工具白名单和严格参数检查
→ TaskDocuments保存绑定轮次的PREVIEW
→ 简短工具结果回到模型，模型组织回答
→ 网页依据真实文档关联显示查看入口
→ 用户在网页明确确认，沿用第19轮文件创建流程
```

模型只提供`plan_id`和正整数`version`，不知道时应先查询，有多个匹配时应澄清。`owner`、`source_turn_id`、去重请求ID、路径及确认均不能由模型传入。同轮同计划版本使用固定请求ID，重复调用只产生同一预览；不同轮次可以产生新预览。

可信调用方通过`open_personal_session(extra_tools=...)`注入本轮工具。WebService只在真实默认日常会话中注入，三人格读取/续接、普通CLI不自动获得它。自定义session_factory替身沿用旧接口，不声称替身已执行真实工具。原ReadOnlyBoundary改名AllowedToolBoundary，继续在模型可见工具和真正派发处检查白名单。

工具只返回文档编号、精确版本、状态、未创建文件标记和后续确认说明，不把整份计划/工作单回灌模型。已有待复核计划查询仍不向模型返回旧正文，工作单本身保持预览时背景提示。

`get_turn`和历史API新增`documents`摘要字段，从持久关联查出，而不是解析模型回答中的“已生成”。因此：模型空口声称生成不会出现入口；工具成功后最终回答失败，轮次仍是FAILED，但真实预览可在历史中恢复并查看。刷新不再调用模型或重新准备预览。

| 标识 | 对象与作用 |
| --- | --- |
| turn_id / source_turn_id | 当前用户消息及模型执行轮次，与真实预览关联 |
| document_id | 第19轮任务文档记录，不是正式计划版本 |
| plan_id + version | 本次工具使用的已保存计划精确版本 |
| 固定request_id | 程序按轮次、计划与版本生成，去除同轮重复调用 |
| payload_hash | 沿用预览内容摘要，最终用户确认仍核对它 |

数据库schema5升级为6，为task_documents增加可空来源外键和索引。旧手动预览保留，来源为空；客户端预览参数不开放来源字段，工具也不能伪造其他owner或非RUNNING日常轮次。

## 3. 预算与使用限制

沿用日常会话现有模型/工具调用上限（默认4次模型、3次工具），不增加自动修复或无限重试。查询计划→准备预览→回答通常需要多次模型调用，本轮真实例子为3次。原生网页若开启自动记忆建议，还可能独立增加至多1次分析；工作单模板与最后确认不调用模型。

模型仍可能误选工具、选错计划或未澄清歧义；提示词不是确定性保证。程序约束工具名称、参数和创建权限，用户负责核对计划与版本。当前单用户部署不等于已具备账号隔离；仍未实现MCP、自动执行计划或AI文档撰写。

终端等客户端共用后端时也可能触发日常预览工具，但本轮只在原生网页实现查看与确认入口；需要打开网页中的同一会话。其他界面的按钮适配未纳入本轮，不把模型文字提示视为已在所有客户端实现交互。

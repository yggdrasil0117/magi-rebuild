# 模块总结 001：单 Agent 执行基础

日期：2026-10-28。状态：本模块基础能力完成；完整 Coding Agent MVP 尚未完成。

## 目标与实际产物

建立可调用模型、受预算约束、能够读取限定目录文件并记录执行过程的单 Agent 基础。用户根据完整参考实现编写代码，助手执行 Review 与相关自动化测试。

| 文件 | 职责 |
| --- | --- |
| `src/magi/agent/response_validation.py` | JSON 解析、顶层与 A/B 示例字段校验 |
| `src/magi/agent/tools.py` | 算术工具定义、注册表和参数校验 |
| `src/magi/agent/runner.py` | 可注入模型与工具执行器的多轮循环、预算、执行事件 |
| `src/magi/agent/file_tools.py` | 限定目录 UTF-8 文件读取与文件工具入口 |
| `expirements/tool_call_demo.py` | 真实模型多步算术工具演示 |
| `expirements/read_file_demo.py` | 指定文档读取、回答与事件展示 |

执行流程：用户消息 → 模型请求工具 → 参数及路径检查 → Python 执行 → 结果追加到模型历史 → 模型继续调用或回答。模型不能直接执行 Python 函数；程序执行工具并控制预算。

## 验证证据

2026-10-28 助手实际执行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_response_validation.py tests/test_runner.py tests/test_tools.py tests/test_file_tools.py -q
```

结果：`50 passed in 0.15s`。这是四个相关测试文件的结果，不是全仓测试或代码质量检查结果。

覆盖的主要行为：JSON 与字段检查、算术工具输入边界、多轮消息传递、不修改原始消息、部分预算停止场景、工具异常传播、文件越界与大小/编码检查、成功与失败事件。

用户提供的真实运行证据：

- 算术任务依次执行 `add(17, 25) → 42`、`multiply(42, 3) → 126`，第三次模型请求返回最终回答。
- 文件任务先执行一次 `read_file`，事件记录成功返回 5533 个字符；第二次模型请求无工具调用，记录 `run_completed`，合计两次模型请求、一次工具调用。
- 文件回答正文未在本次总结中核对，因此不将事实准确性列为已验证结果。

## 已知边界与待办

- `run_completed` 表示模型正常结束调用，不证明用户任务完成。
- 事件在内存中，记录工具名和结果长度，不含文件路径、内容摘要或证据编号，不能提供完整来源追踪。
- 路径解析检查适用于当前本地实验，不防御其他进程并发替换文件的竞争条件，也不是系统沙箱。
- `max_bytes` 尚未验证正整数；当前使用程序固定默认值，模型不能指定。
- 预算测试未完整覆盖累计多轮、同批多个调用和非法配置等情况。
- 读取失败直接终止，没有让模型自主恢复；同批多工具不提供事务原子性。
- 未实现任务副本、代码修改、差异交付、Docker 测试执行与三人格复核。
- 依赖声明及旧 README 的环境说明仍需在正式可复现运行入口建设时同步整理。

## 学习收获与过程记录

已练习 JSON 与字典的区别、短路判断、异常捕获与重新抛出、函数作为值、参数展开、闭包、路径处理、依赖注入、模拟模型测试与事件记录。

典型问题及纠正：字典误用属性访问；循环中提前返回；测试输入未到达目标分支；测试代码放入运行模块导致循环导入。后续采用“完整参考实现 → 解释 → 运行 → 小改动 → 集中 Review”，按功能组织学习。

工具故意返回 999 的实验还说明：模型可能否认工具结果并自主回答。模型判断不能替代程序侧对测试、文件操作及交付条件的验证。

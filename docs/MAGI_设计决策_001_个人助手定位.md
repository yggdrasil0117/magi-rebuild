# 设计决策 001：个人助手定位与增量开发

日期：2026-10-28。状态：用户已确认。当前基准：[设计 v0.2](MAGI_产品与技术设计_v0.2.md)。

## 背景

此前产品围绕三人格协作 Coding Agent 设计。用户进一步明确：真正希望长期使用的是可以聊天、建议、跨领域行动并延续上下文的个人助手，同时通过开发学习 Agent 和后端，并服务求职。开题研究聚焦非完备规约和软件符合性验证，适合保持专业模块边界。

## 决策

- 主产品调整为长期个人 AI 助手，首批场景为学习、科研、求职。
- 默认一个连续对话入口；三人格在用户主动审议时启用，普通聊天不强制调用三个人格。
- 第一版完成持久对话、已确认记忆、资料整理与计划保存/更新、任务结果和审议闭环。
- 代码开发与符合性验证保留为专业能力；独立维护论文实验边界。
- 从当前仓库增量开发，保留已完成执行循环、工具、证据与测试，不整仓重建。
- 模型接入集中配置并隔离提供方差异；SDK/框架按任务试验选择，OpenHands 不再作为全产品的既定底座。
- 盘点既有知识与行动 Agent 的复用点；简历中的能力不直接记作 MAGI 已实现。

## 替代方案与选择理由

继续纯 Coding Agent 能贴近软件研究，但未覆盖用户主要使用动机。立刻建设全领域自治终端范围过大，难以学习和验收。当前采用稳定愿景加有限个人工作场景，以跨会话真实使用验证产品价值。

## 代价与控制

会话与记忆优先级提高，隔离代码修改和测试执行后移。暂停继续把项目进度报告打磨成独立产品；保留其语义和资料时效失败案例。后续通过 PA 验收及模块总结控制扩展，每次增加能力都要能完成一个真实任务。

## 已实现与待实现

现有执行循环和文件工具可复用，持久会话、长期记忆、计划写入、三人格和产品界面均待实现。此次文档调整不新增运行时依赖，不迁入外部项目，不改变业务代码。

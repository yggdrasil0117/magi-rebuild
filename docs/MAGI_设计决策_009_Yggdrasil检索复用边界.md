# 设计决策009：Yggdrasil检索复用边界

日期：2026-11-01。依据：用户要求先检查企业文档检索项目，能复用则复用，不能复用再扩建MAGI。本轮为复用评估，不声称已经接入MAGI服务。

## 1. 决策

**有条件复用Yggdrasil的检索与证据服务，暂不在MAGI重建文档摄取、向量索引和知识库平台。**

代码和专项测试支持“组件有复用价值”；当前证据不支持“检索普遍可靠”或“可以直接拿最终回答作为决策事实”。是否复用组件与是否通过产品端到端质量验收是两个问题。具体证据见[模块025总结](MAGI_模块总结_025_Yggdrasil检索复用评估.md)。

下一轮目标为资料驱动审议，先接取证能力，再验证引用与建议。当前默认日常聊天和已有本地关键词检索继续独立可用，不将外部知识库变成整个MAGI的启动前提。

## 2. 服务职责

```text
用户问题 → MAGI选定本次资料范围
                 ↓
         Yggdrasil Core检索/证据API
                 ↓
         原文、来源、文档版本、摘要
                 ↓
         MAGI冻结本轮审议输入
                 ↓
         三人格分析 → 带引用候选 → 用户确认
```

- Yggdrasil负责文档摄取、分块、全文/向量检索、可选精排及自身身份/资料权限检查。
- MAGI负责个人目标、记忆、三人格权衡、证据不足和分歧表达、确认保存及反馈修订。
- 通过Core API复用，不直接查询其数据库或复制企业权限逻辑；不把旧MAGI适配器的生成链路再接回来形成循环依赖。
- 生成继续使用MAGI已配置的千问；检索服务不必调用Yggdrasil的4B回答模型。BGE嵌入/精排仍有独立资源成本，不能将“不用4B”说成“不占本地模型资源”。本轮没有启动BGE或向Ollama发送生成请求。
- 首版可用HTTP适配，MCP不是前置条件。未来即使通过MCP暴露，同一权限、证据和预算合同仍然有效。

## 3. 可复用接口与数据

已检查的Core接口：

| 接口 | 返回/行为 | 接入注意事项 |
| --- | --- | --- |
| `POST /api/v1/retrieval/search` | 原文候选、来源和版本、评分、实际provider和精排标记 | 候选不是答案；limit为1～20，query最多1000字符；显式传sourceIds |
| `POST /api/v1/retrieval/evidence-packages` | 重新检索并将结果写成冻结证据包 | 会真实写入Yggdrasil数据库，不是无副作用的只读查询；purpose可选answer/compare/investigate |
| `GET /api/v1/retrieval/evidence-packages/{id}` | 校验当前访问条件及包摘要后读取 | 曾有权限不等于现在仍可用；不能只凭旧包ID绕过再次鉴权 |

查询条件中的sourceIds不能代替身份认证。MAGI本机服务凭据不能直接当成Yggdrasil登录凭据。连接凭据及允许检索范围由服务端绑定，不让模型传入任意租户身份或管理凭据；开发用`X-Ygg-Local-Identity`不是正式用户登录方案。

| ID/摘要 | 标识对象与用途 |
| --- | --- |
| sourceId | Yggdrasil资料来源，用于限制查询范围 |
| documentId | 资料中的文档身份，可能对应多个版本 |
| documentVersionId | 本次实际引用的文档版本；不等于MAGI计划版本 |
| chunkId | 该文档版本中的正文分块 |
| evidencePackageId / evidenceItemId | 一次冻结证据包及包内条目，供回查 |
| contentDigest / packageDigest | 内容/证据包完整性摘要，不证明事实正确或资料最新 |

上述对象都不能替代MAGI的turn_id、候选ID、plan_id、operation_id或memory_id；外部资料被引用也不会自动成为用户长期记忆。

## 4. 首次接入必须处理的具体缺口

1. **相关性与充分性分开。** 不以候选非空、冻结成功或单个分数达标认定问题已经得到回答。保留不支持、冲突、未查到的表达，人工复核引用是否支持结论。
2. **评分来源不能混用。** search返回provider/精排标志，但冻结包没有保留这些执行元数据。首版可明确标成评分来源未知，不使用统一阈值；若要自动阈值判定，需要上游在同一次冻结检索中保存实际执行信息。先search再freeze是两次检索，不能把第一次元数据冒充第二次的事实。
3. **文档版本策略。** 默认检索可以同时返回旧版和新版。比较历史时有用，回答“当前规定”时必须依据版本/生效信息作选择或提示冲突，不能仅凭排序第一条、发布时间较晚或模型猜测宣布某版有效。
4. **故障与降级如实显示。** 当前嵌入失败直接中断；精排不可用有降级分支。不要把外部知识库失败悄悄换成本地docs目录后继续声称检索了同一批资料。
5. **引用与访问状态。** 原文与本轮快照关联；后续新审议/重新取证要重新确认可访问性。跨系统保存片段后如何显示撤权历史，需要在接入合同中明确，不把一个成功GET当永久授权。
6. **上下文有界。** 限制片段数、正文总量、请求时限；保留文档版本及原文定位，截断时标明范围。资料文本是数据，不能成为授权工具或改变系统指令的来源。

## 5. 验收与扩建条件

下一轮用合成资料和少量用户认可的真实任务验证：有答案、同义问法、无答案、旧新版本冲突、不可访问来源、检索失败，以及三人格引用核对。固定所有尝试，分开报告程序边界、检索质量、建议内容、延迟与token成本。

只有具体阻塞出现时才扩建对应部分：索引/模型部署成本不适合时评估轻量检索或云端嵌入；召回不足时对照关键词、向量与混合检索；引用合同缺字段时补适配或上游接口。不要因为评测样本小就推倒整个知识库，也不要为了证明复用而隐藏失败。

这一决策不承诺下一轮必须启动本地模型，不建设新的账号平台或工具市场。本轮完成后先由用户阅读结论，再推进接入。

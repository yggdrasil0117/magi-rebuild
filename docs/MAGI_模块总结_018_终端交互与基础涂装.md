# 模块 018：终端交互与基础涂装

日期：2026-10-30。

## 本轮目标与结果

增加独立终端入口，通过现有 HTTP API 完成聊天 → 三人格候选 → 用户复核 → 明确确认保存。终端和网页连接同一服务、使用相同会话名时，共享历史和真实保存结果。终端没有另建模型、Agent、记忆或计划服务。

用户补充参考 [Ax1i1om/NERV-CODE](https://github.com/Ax1i1om/NERV-CODE)，并明确只参考 UI 与前端，不引入 CCSourcemap 核心。已读取该仓库公开 README 的配色与界面说明；没有下载、执行或移植其核心代码。GitHub API 限流后改为只读 raw README。

当前具有暗红 `#B7282E`、终端黑 `#0A0A0C`、正文白 `#E8E6E3`，讨论详情标题可用紫 `#6B3FA0` / 橙 `#E87D2A` 强调。紫橙当前只是三人格详情的视觉强调，不意味着已新增初号机或零号机子 Agent。

## 运行与操作

在项目根目录打开两个 PowerShell 窗口。

窗口一保持后端运行：

```powershell
.\scripts\start_magi.ps1
```

窗口二打开终端客户端：

```powershell
.\scripts\start_terminal.ps1
```

隐藏输入窗口一给出的“本次服务凭据”，不是千问 API Key。也可从进程环境变量 `MAGI_API_TOKEN` 读取，客户端不保存凭据。默认 `study` 与网页默认会话相同；可传 `-Chat other_chat` 使用不同会话。客户端不会自动启动本地模型。执行策略受限时使用 `powershell -ExecutionPolicy Bypass -File .\scripts\start_terminal.ps1`。

直接输入一行文字发送。`/council` 开启三人格，`/chat` 返回日常聊天，`/history` 读取会话，`/details` 展开最近候选的讨论，`/save` 复核冻结候选。只有输入完整的“确认保存”才提交保存请求，其他输入取消。

`/retry` 使用原消息重试，`/discard` 放弃客户端重试并读取历史，`/quit` 退出。放弃或退出不撤销服务端操作。终端颜色不适配时使用 `-NoColor`，非 TTY 输出自动禁用颜色与动画。

## 文件与调用关系

- `src/magi/terminal.py`：标准库 HTTP 客户端、输入命令循环、等待动画和候选确认；没有新增依赖。
- `scripts/start_terminal.ps1`：使用已有虚拟环境启动客户端。
- `tests/test_terminal.py`：复用离线后端环境，验证断线、确认、共享历史与真实本机 HTTP 连接。
- README 新增终端入口说明。原网页、后端和数据库结构不变。

业务路径：`Terminal.command` → `send` → `/v1/chat` 或 `/v1/deliberations`；`save` → 读取绑定候选 → 展示候选正文 → 用户确认 → `/confirm` → 后端校验并写库。

## ID、失败与保存边界

- `chat_id` 标识会话，跨客户端重启保留；网页与终端共享会话需使用相同值。
- `message_id` 标识一次用户消息，`reply_message_id` 标识其预期回复；新消息创建，重试保持不变。
- `parent_reply_message_id` 指向前一条回复，用于后端上下文检查，不是计划版本。
- `proposal_id` 标识后端冻结候选，必须同时匹配会话、回复及 `payload_hash`；不是保存证据。
- 保存成功以后端操作回执的计划版本为准；重新连接则读取候选对应的已提交操作状态。计划 ID 与操作回执仍由后端管理。

消息响应丢失时，客户端保留完整请求，阻止新输入替换；重试复用后端幂等能力。确认响应丢失时保留已经明确确认的原载荷，后续 `/save` 重试同一操作，不能换成另一个候选。

模型生成、结构校验、COMPLETED、用户确认、数据库提交依然是不同事实。客户端不直接写库。仅允许本机 HTTP 地址，禁用代理与跳转；服务端文本清除终端控制字符，凭据不放入 URL、命令行或记录。

已验证：普通聊天、三人格四次模拟调用、消息响应丢失后不重跑模型、取消不写入、保存响应丢失后只保留一个计划版本、新客户端恢复已保存状态、真实 urllib → 本机 Uvicorn → FastAPI → 临时 SQLite、错误认证拒绝、非本机地址拒绝、控制字符过滤。测试中的客户端重建不是操作系统进程重启或真实 checkpoint 重启验证。

## 当前限制与学习重点

启动标识是叶片字符画示意，还不是参考截图的 NERV 像素徽章。64 条加载文案由 16 个 EVA 意象与 4 个动作组合，不是 64 条独立编写的台词；每次请求随机选择一条，六角形交替动画，不展示真实模型阶段。现阶段是行式 CLI，不是全屏 TUI：不支持流式回答、输入框多行编辑和真实子 Agent 进度。终端黑用于输出背景，不修改 Windows Terminal 的全局配置。

本轮未修改网页主题；记忆管理、计划历史/版本比较及反馈修订继续使用网页。没有自动触发记忆提取，普通回答仍会使用后端已有已确认上下文。核心未提交改动 `src/magi/council/service.py` 和已有 `docs/validation/markdown` 不属于本轮，交付时不混入提交。

推荐阅读顺序：`send` 理解“消息编号用于重试”，再看 `save` 理解“确认绑定冻结候选”，最后看后端 `WebService.confirm` 理解“真正保存发生在哪里”。可选复述：为什么关闭终端或放弃重试，不能说明服务端没有写入？本轮结束后等待用户体验和阅读，不继续扩展下一轮功能。

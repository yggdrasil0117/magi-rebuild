# 模块总结 002：文件调查与证据验收

日期：2026-10-28。当前状态：程序实现与相关测试完成，真实执行与引用链验收通过；资料选择、时效与结论内容验收未通过。下文保留各次迭代记录，最新结论见末尾补记。

## 设计对照

对照产品设计 §5 验收、§7 事件与职责、§8 工具边界：新增文件发现、每次调查独立的证据登记、结构化报告校验及程序生成来源路径。尚未实现语义支持核验、文档时效元数据、持久化和三人格共享证据。

## 代码与调用链

- `file_tools.py`：单层文件发现、有界枚举最多 100 项；整文件读取上限现为 32768 字节。
- `investigation.py`：`EvidenceSession` 绑定目录和读取预算，只在读取成功后生成 E1 等编号，保存规范相对路径、正文和正文 UTF-8 SHA256；`records` 返回副本。
- `validate_report()`：检查 JSON、字段、结论、引用和不确定性；拒绝未读取的引用和没有任何成功读取的报告。
- `render_report()`：根据程序证据表生成来源路径，不采用模型编写的路径。
- `read_file_demo.py`：工具循环结束后再验收报告；验收通过记录 `report_validated`，ValueError 记录 `investigation_rejected` 并继续抛出。

哈希绑定的是实际返回的正文内容，不是 Git 提交、磁盘文件身份或完整验证环境。证据编号仅在当前会话有效。重复成功读取也消耗预算并生成新编号。

## 失败案例与取舍

曾因执行入口漏分支返回 None，runner 将它转成文本传给模型；证据包装层现明确要求文件工具返回字符串。旧记录的工具成功仅代表没有异常，不等于业务结果有效。

曾因设计文档超过 16 KB 读取失败，随后调整为 32 KB 并测试边界。更大的文件仍需后续分段读取，不能无限扩大限制。

提示词无法单独保证来源真实，因此把引用登记、读取预算、报告验收放到程序层。提示词仍描述格式与资料选择原则，但输出不合格就拒绝展示为验收通过的报告；暂不自动重试。

## 已知限制与下一步

- 合法引用不证明原文支持结论；未处理语义矛盾和文档时效的确定性选择。
- 初版仅提示要求 JSON，真实运行出现非 JSON 回复，被验收正确拒绝。现拆为工具调查与独立报告生成：后者不传 tools，传入动态 JSON Schema（引用编号限定为本次证据），最多额外请求一次，之后仍执行引用校验。新真实运行待验证。
- 路径检查不提供操作系统沙箱，也未消除并发路径替换竞争条件。
- 列表最多 100 项，但尚未设置总输出字符上限。
- 报告验收与 Agent 循环完成是两层状态；`run_completed` 不等于报告合格。

下一步：运行新版 `read_file_demo`，核对证据引用及内容；通过后补记真实验收证据，再进入隔离修改与测试执行。

修正验证：加入报告阶段使用 schema 且不传工具、即使生成端返回虚构引用仍拒绝的两项测试；同样五个相关测试文件结果更新为 71 passed in 0.35s。报告请求不计入 runner 的调查预算，本演示最多 6 次调查模型请求加 1 次报告请求。调用失败或报告不合格不自动重试。

第二次真实运行发现：列表加两次读取已耗尽工具预算，模型仍要求继续调用，程序正确报超限。现增加可选 `should_stop` 应用停止条件；演示在整批工具执行后，若已读取两个文件，记录 `run_stopped` 并切换报告阶段，不等待模型自行结束调查。未提高预算，也不吞掉一般预算异常。停止仅表示达到调查范围，不保证证据充分或最终任务成功；同批超预算仍在执行前拒绝。新增停止条件测试后五个相关测试文件 72 passed in 0.37s；真实完整验收仍待运行。

后续真实运行发现模型为列表工具提供空字符串。调整列表工具契约：空白字符串与 `.` 均表示绑定根目录，只归一化列表路径；读取文件仍拒绝空路径，非字符串与目录越界规则保持。新增三种目录输入及读取空路径拒绝测试，五个相关测试文件结果 76 passed in 0.55s。新版真实模型完整验收仍待运行。

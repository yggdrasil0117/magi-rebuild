# 设计决策003：自动提出记忆候选，用户确认后生效

日期：2026-10-30。用户已授权先补设计再实现。原v0.2第8节已有“普通聊天推测出的候选先等待确认”原则；本决策补充有界实现，不引入大规模抽取、向量库或自主记忆写入。

## 交互

成功回答后，原生网页自动请求一次独立提取。只读取该轮用户原话和当前有效全局记忆，不使用助手回答、旧计划、文档内容或人格意见作为用户事实来源。模型筛选稳定偏好、背景、长期目标；临时安排、假设、引用他人及推测性标签不应提出。

有建议时显示“是否记住？”卡片，包含内容、原话依据、理由；同名旧记忆不同值时显示替换前后内容。用户可以修改内容、确认或忽略。手动管理入口继续保留，模型不直接写有效记忆。

## 成本与执行

- 每条成功消息最多一次独立提取调用、最多一条候选；输出最多512 tokens、读取响应配置最多20秒，无自动重试。HTTP分阶段超时不等于墙钟硬取消，迟到结果不接受。原三人格仍最多4次，完整页面流程最多额外1次，不能混称总共4次。设置中可暂停自动提取，仍可处理已有候选。
- 回答先返回，再由网页请求提取，不等待提取才能展示回答。模型等待不占主生成串行门，只在读取快照时短暂使用它。提取进程内单并发，忙时跳过。
- 刷新历史只读已有结果，不再次请求模型。失败和重启中断记录状态，不自动重放。其他界面与CLI不自动提取。
- 当前epoch最多3条待确认候选，超过则不继续提取。输入快照过长时跳过，不静默裁剪。

## 依据与去重

复用程序原文片段目录，让模型选编号、程序补入原文。允许不提出候选；无效来源、不合格结构或超时均不写有效记忆。

按空白与大小写归一化后的名称、内容去重，包括已忽略候选；同名不同值绑定旧记忆ID及版本，等待用户确认替换。不同名称的语义重复不保证识别，不自动合并。模型的长期价值判断可能出错，确认不可省略。

## 持久化与确认

新增提取尝试与候选记录，绑定owner、会话、轮次和epoch，与有效memories分离。提取不改变epoch。

确认时冻结用户编辑内容，用候选ID构成固定操作ID，复用MemoryService事务和版本校验；完成后才推进epoch。重复确认返回原回执。若记忆写入后、候选状态更新前中断，按操作记录恢复，不重复写入；同一候选不能覆盖已提交值。

忽略不变更有效记忆或epoch；过期候选不能确认，但已提交操作可查询原结果。确认与忽略仍使用主串行门。当前仍是单用户实例，owner字段不等于完成多租户隔离。

## 验收

离线覆盖无候选、有效候选、非法来源、去重、同名更新、忽略、编辑确认、重复及改变内容确认、epoch过期、失败重启不重放、跨owner拒绝访问、写入后恢复。提取失败不影响原回答。

真实浏览器验证自动提出、确认/忽略、刷新恢复、确认前不生效；真实模型另做固定小批样例，保留无候选及失败，不将小样本当普遍准确率。常规功能不自动写入question.md。

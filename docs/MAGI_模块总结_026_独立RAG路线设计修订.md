# 模块026：独立RAG路线设计修订

日期：2026-11-01。本轮只修正设计文档，不实现RAG代码、不改变数据库、不调用模型。

## 1. 为什么修订

第25轮证明Yggdrasil检索组件具有复用价值，但用户进一步明确：Yggdrasil的RAG主要由Coding Agent完成，自己没有完整参与设计和实现。MAGI同时承担学习Agent与后端的目标，若下一步直接调用Yggdrasil服务，关键检索链路仍是黑箱。

因此本轮根据用户确认，将路线从“运行时复用Yggdrasil检索服务”调整为“MAGI独立实现面向个人资料的RAG，Yggdrasil只作参考和评测对照”。这不是否定第25轮的审查结果，而是改变如何使用这些结果。

## 2. 修改后的正式路线

- `RetrievalProvider`是MAGI内部能力接口，不绑定Yggdrasil；首个实现为`MagiLocalRetrievalProvider`。
- MAGI代码、数据、启动和核心流程不依赖Yggdrasil在线。
- 从已有有界文件搜索出发，逐步实现文档版本、分块、关键词/BM25、证据快照和三人格引用。
- Yggdrasil的权限过滤、证据完整性、版本冲突与历史评测只作为设计参考和对照，不复制其Java服务、企业权限或数据库迁移。
- 当前不自动启动本地4B模型、BGE或其他本地嵌入模型；先得到关键词基线，再由固定评测决定向量召回、融合和重排。
- RAG服务于个人决策与行动，MAGI不改成企业知识库产品。

完整决定见[设计决策010](MAGI_设计决策_010_独立RAG学习与演进路线.md)。[设计决策009](MAGI_设计决策_009_Yggdrasil检索复用边界.md)和[模块025](MAGI_模块总结_025_Yggdrasil检索复用评估.md)已标记为历史评估，保留当时证据，避免把历史结论改写成从未发生。

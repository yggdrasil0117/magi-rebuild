# MAGI 模块总结 016：网页个人记忆管理

日期：2026-10-30。对应整体计划v0.3中的P1“记忆管理界面”，复用004A已有记忆机制，不新增自动提取或向量数据库。

## 1. 本轮完成什么

连接服务后点击“个人记忆”，按需查看有效的全局背景与偏好。添加记忆只需名称和内容；修改、删除由列表按钮进入，不填写ID或版本。

每次写入先显示确认预览，修改时并列列出原内容和新内容，删除时明确显示要删除的记录。只有最后的确认按钮才发写请求；取消预览不修改数据库。

普通聊天和保存计划都不会自动添加个人记忆。已确认的记忆会作为后续聊天与审议的有效上下文，而计划仍保存在独立的版本计划机制中。

## 2. 调用链与一致性

```text
查看列表 → GET /v1/memories
填写或选择记录 → 本地确认预览
用户确认 → 带认证、请求ID和预期版本的记忆命令
  → WebService.change_memory获得与审议共用的串行门
  → MemoryService事务：记忆变更 + 操作回执 + context_epoch递增
下一次对话 → 重新读取有效记忆 → epoch对应的新checkpoint段
```

接口仅支持全局记忆：`POST /v1/memories` 添加，`/{id}/update` 修改，`/{id}/delete` 删除。所有读写均需现有凭据。未提供严格布尔确认、字段不合格或客户端试图指定来源等额外字段时拒绝请求。

页面冻结预览内容与请求ID，失败后重试原请求，不把后续编辑内容悄悄换进去。请求ID绑定当前用户并与CLI命名空间隔离。重复同一操作返回原回执，不再次递增epoch；同ID换内容拒绝，更新或删除的旧版本请求也拒绝。

新增记忆的来源由服务端固定为 `explicit_web`；原有CLI入口继续使用 `explicit_cli`。模型没有新增记忆写工具。网页写入与生成共享串行门，审议运行时修改返回BUSY，避免同轮中途改变背景。

## 3. 删除与背景失效的含义

删除后记录标记为DELETED、版本递增、当前记忆正文置空，后续不再作为有效记忆加载。但历史聊天、已保存计划、旧回合快照等不会因此被清除；本轮不是全库隐私擦除功能。

任何记忆变更都会推进context_epoch。因此已有未保存候选不能继续按旧背景保存，需要重新生成；已保存计划仍保留，但标记需要复核。当前仍沿用既有规则：旧背景计划可能被拒绝直接修订，本轮没有新增网页重确认背景或计划重基线功能，不能绕过该边界。

修改记忆不意味着立刻改变模型正在生成的内容，也不保证模型一定遵从偏好；这里保证的是后续输入使用当前有效版本。取消失败操作的重试不等于撤销服务器可能已经完成的提交，页面会提示刷新核对。

## 4. 验证总结

全套离线验证：**283 passed，19.59秒**，一个已有Starlette/AnyIO弃用警告；变更Python文件Ruff与格式检查、两个前端脚本语法检查通过。

新增四项集成测试覆盖：

- 鉴权、严格确认、额外来源字段拒绝、添加/修改/删除及重复请求、版本冲突、删除正文置空。
- 模型运行串行门占用时记忆写入返回429，epoch不改变。
- 记忆变更后旧候选保存被拒绝；下一轮使用新记忆和新的有效thread段。
- 服务对象重建后读取既有全局记忆，其他会话专属记忆不出现在页面目录，网页也不能按ID删除它。

真实Edge通过Playwright CLI连接独立FastAPI和SQLite，模型与checkpoint为桩，没有调用千问或本地模型。实际验证：

1. 添加预览时，数据库记忆数仍为0，epoch仍为0。
2. 确认添加后得到v1，再修改并确认得到v2，新值为“先给具体例子，再解释原理”。
3. 浏览器发送一次模拟审议，其输入快照实际带入该新值，epoch为2。
4. 取消删除后，记录仍为ACTIVE v2，epoch仍为2。
5. 确认删除后为DELETED v3、当前正文为空、epoch为3；再次发送模拟审议，输入快照的memories为空。

最终6次操作中3次为预置演示计划、3次为确认后的记忆变更；预览和取消不产生操作，浏览器中的审议候选未保存。两个模拟审议有8次桩调用，不是8次真实模型请求。

## 5. 代码阅读与范围

先读 `web/schemas.py` 的记忆命令，理解确认、请求ID和预期版本；再读 `WebService.change_memory`，理解串行门如何复用已有事务。最后读 `memory.js` 的 `previewMemory` 和 `confirmMemory`，区分本地预览与真实写入。

页面只管理全局记忆，没有会话专属编辑、自动提取、RAG或记忆检索排序。本轮主要是已有机制的网页入口，不为凑重大问题条目写入question.md。

# MAGI 模块总结 010：跨场景云端验收与函数导读

日期：2026-10-30。当前兼容结构已完成一批真实千问验收，**兼容能力得到验证，稳定性尚未通过**。

## 1. 本轮实际结果

使用千问 `qwen3.8-max`，固定四个场景，每个场景创建、修订各一次，共八轮，没有自动重试、替换失败样例或修复后覆盖记录。

| 场景 | 创建 | 修订 |
| --- | --- | --- |
| 出差费用，无分钟预算 | 原文摘录不匹配，PARTIAL | 综合超时，PARTIAL |
| 采购选择，无分钟预算 | BALTHASAR 超时，PARTIAL | COMPLETED |
| 接口排查，无分钟预算 | COMPLETED | COMPLETED |
| 学习安排，有分钟预算 | 原文摘录不匹配，PARTIAL | COMPLETED |

四轮完成，四轮未完成。独立边界检查八轮均通过，含义是失败时没有产生可保存候选、调用没有超预算等，**不是八轮都成功**。脚本正确返回非零退出码，表示整批稳定性验收未通过。

实际模型调用 31 次：采购创建的人格失败后没有综合，因此少于上限 32 次。29 次有完整用量，已知输入 17807、输出 5429、合计 **23236 tokens**；另两次超时缺少用量，不能当成零，也不能把已知数当成平台最终账单。

整批耗时 289.969 秒；单轮最短 26.031、中位 30.117、最长 76.188 秒。本批案例、提示和模型输出结构不同于 007，不能据此计算质量或速度提升百分比。

## 2. 兼容性与内容质量分别怎么看

真实成功的采购修订没有填写分钟，也没有活动标签。它根据上限从 1300 降到 1000，排除价格 1200 的 A，要求先验证 900 元 B 的兼容性，再决定是否购买，没有把兼容未知写成已确认。

接口排查使用“排查、分析”等自定义标签，分钟为 null；学习修订使用“学习、实践、复盘”，30+45+15=90。说明可选字段和自由标签在真实模型调用中能够工作，无需强制所有计划进入 rest/review 分类。

金额只是这些虚构案例提供的已知条件，人工核对模型回应；**没有新增金额计算或费用超限的程序校验**。出差两轮都失败，没有获得可评审候选，不能声称出差预算建议已通过。

对全部四份成功候选逐一人工复核：两份在所列假设成立时清楚；另两份需要澄清。

- 接口修订正确跳过了重复收集复现，但完成条件要求最终得出明确根因。证据可能仍不足，应允许记录未解决问题与下一项检查。
- 学习修订的时间合计正确，却取消旧计划中的休息，依赖“用户能连续专注90分钟”的未确认假设。这个取舍需要用户确认，算术不能替用户决定。

原文摘录失败的两份综合内容未被保留，这是现有诊断的隐私边界；因此本记录只能确认匹配失败，不能还原具体改写了哪个字，不进行推测性归因。

## 3. 本轮代码与验证

`scripts/evaluate_council.py` 新增 `--suite compatibility`，保留原始案例集作为默认值；记录选中案例的指纹与计划轮数，报告不会把四案例误算成原来的三案例。增加缺失密钥的提前检查，避免把配置缺失误报为整批模型质量失败。

独立评测增加行动与完成条件检查，缺少步骤、缺少行动或空完成条件均不算通过。评测不执行步骤，也不调用计划保存接口。

按照用户阅读需求，新增或补充核心函数的中文说明：

| 函数 | 可以怎样理解 |
| --- | --- |
| `build_snapshot` | 把固定案例整理成一轮审议输入；修订使用预设旧计划，便于独立比较 |
| `Council.run` | 同一份快照交给三人格，再综合；返回结果，不保存计划 |
| `_invoke` | 适配模型平台；这里的 budget 是输出 token 上限，不是用户的分钟预算 |
| `_generate` | 读取模型结果、记录用量、解析字段；失败交给上层处理，不自动重试 |
| `check_content` | 核对来源和条件性用时要求，不能判断所有语义问题 |
| `candidate_body` | 把候选变成网页展示和确认保存共用的正文，不写数据库 |
| `generation_schema` | 给本次生成更具体的字段要求，仍保留旧计划读取兼容性 |
| `assess_result` | 独立核对一轮结果的程序边界，不给内容打正确分 |
| `summarize_report` | 汇总所有尝试，区分成功、失败、已知和缺失用量 |

最终全套离线验证：**263 passed，17.04 秒**，一个已有 Starlette/AnyIO 弃用警告。四个变更 Python 文件 Ruff 检查与格式检查通过。

本轮真实验收只覆盖 Council，不包括新的浏览器、确认保存、重启或 Open WebUI 验收；这些能力的已有验证仍见前轮记录。真实运行代码相对基准提交有本轮改动，报告同时保留源码指纹，不把基准提交误当作全部被测源码。

记录：[完整云端结果](validation/010-cloud-compatibility.json)、[逐项人工复核](validation/010-semantic-review.json)。无密钥内容进入报告或仓库；运行密钥只传入本次子进程环境。

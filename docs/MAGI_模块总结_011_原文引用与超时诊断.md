# MAGI 模块总结 011：原文引用与超时诊断

日期：2026-10-30。已实现并完成离线与真实千问验证；引用复制失败得到改善，超时可定位到阶段，整体稳定性仍未全部通过。

## 1. 引用从“抄原文”改成“选原文”

之前让模型自己生成摘录，再逐字匹配用户消息。模型即使意思接近，只要改了标点或措辞，也可能导致整份候选被拒绝。

现在由 `source_options(snapshot)` 从当前消息和有效记忆中生成有界目录，每项带编号、来源和原文；模型只填写 `source_ids`。程序通过 `selected_excerpts` 查本轮目录，填入对应 `source_excerpts`，再做原有来源核对。

```text
当前快照 → 程序原文目录 → 模型选择编号
  → 程序填入原文 → 校验 → 冻结候选 → 等待用户确认
```

这不是用模糊匹配放宽标准，也不是自动改写模型内容。未知编号、重复编号和同时混用编号与手写摘录会被拒绝。空选择仍然允许，不强制制造引用。

目录最多24项、每段最多160字，按当前消息、记忆的顺序切分，不增加模型调用。超长输入只有部分片段进入引用目录；固定切分可能截断句子，引用的相关性和上下文含义仍需复核。历史回复、旧计划和人格意见不会登记成当前用户陈述。

`source:0` 等编号**仅在本轮目录中有效**，不是对话 ID、业务对象 ID 或保存回执。保存候选时会保留实际摘录和来源，不依赖重启后重新解析编号。旧候选没有 `source_ids` 仍能读取，旧手写摘录仍按原规则严格检查，无需数据库迁移。

## 2. 超时现在能说明什么

新增超时诊断区分：

- 单次请求：连接、读取响应、发送请求、等待连接池；异常链没有明确类型时记录“阶段未知”。
- 整轮期限：发起下一阶段前剩余时间已耗尽，或结果返回时整轮期限已过。

只记录受控类型与已有阶段耗时，不保存异常正文、请求头、URL 或密钥；网页失败说明也会带上中文阶段。

千问适配层设置连接最多10秒、发送最多10秒、连接池最多5秒，读取响应沿用配置，本次60秒；各值均不超过调用方给定的请求超时。这个共享适配层同时影响日常聊天和审议。仍然 `max_retries=0`，不增加重试、备用模型或调用上限。

**HTTP 分阶段超时不是整个同步调用的硬性墙钟上限。** 整轮上限仍按原规则最多240秒；程序不会强行杀死正在执行的同步请求，但会拒绝整轮期限之后才返回的结果，并停止启动后续阶段。离线测试验证了迟到结果不被接受。

连接超时说明未在连接阶段完成，不足以判断是本机网络、路由还是平台问题。没有证据时不猜测根因，也不把超时当成内容质量错误。

## 4. 内容问题仍需分开处理

对七份成功候选逐项复核，三份在所列假设成立时清楚，四份需澄清，不能把七份完成理解为七份内容正确：

- 采购创建把未说明的产品具体化成设备部署，且“稳定运行无故障”缺少验收范围。
- 接口修订的最后一步已允许留下验证缺口，但某一步仍预设要排除连接池耗尽，未允许发现它正是原因。
- 学习创建两段休息都写“累计满10分钟”，是否各休息10分钟不够明确。
- 学习修订仍把复盘当成可以替代休息的假设，取消了休息，没有先取得用户对此取舍的确认。

本轮给综合提示增加了证据不足可保留缺口、重要取舍需确认的通用指引。实际结果说明提示有所帮助但不可靠，没有新增固定活动分类或宣称通用语义校验已经完成。

下一轮优先围绕“证据不足时怎样算完成、重要取舍怎样交给用户决定”设计通用交互；超时继续依据类型排查，不盲目增加重试。完成本轮后先等待用户阅读复述，纠正理解后再推进。

## 5. 函数阅读建议

先读 `sources.py` 两个短函数：`source_options` 准备可选原文，`selected_excerpts` 用编号查表。再看 `service.py` 中综合结果怎样补入原文并生成正文。最后看 `generation.py` 的 `timeout_diagnostics`：它沿异常原因链寻找已知超时类型，不读取异常中的敏感文字。新增与修改的关键函数均保留中文说明。
